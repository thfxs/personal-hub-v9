# Personal Hub 1.7：Android 原生安全配对、同步与快捷指令

本说明面向荣耀 V9 上最终安装的 **Personal Hub Android APK**。当前版本是源码与 CI 构建准备，不是已经在荣耀 V9 验收的安装包。为保护原 APK 的数据，预览版仍使用独立包名 `dev.personalhub.v9preview`；它不会自动继承旧 APK / GitHub Pages 的 IndexedDB。

## 安全机制（与 1.6 的区别）

- 1.6 的 APK 页面无法从本地源安全请求电脑私有 HTTPS 接口；1.7 新增 `PinnedBridgeClient.java` 的 HTTPS 专用原生客户端，**不经 WebView 的 HTTP 混合内容或任意 CORS 放开**。
- 首次连接需要手动抄写/核对电脑本机显示的 SHA-256 **完整证书指纹**，固定到 APK 本地偏好。只准填 RFC1918 私有 IPv4，证书 IP SAN 必须与输入的电脑地址一致，证书不得过期。指纹变更时拒绝连接，必须手动重新核对，**不提供忽略证书错误的按钮**。
- 配对时采用电脑端 8 位临时 PIN。服务器返回的 HttpOnly 会话 Cookie 仅保存在 Java 内存，不通过 JavaScript 读取，也不会写入本地存储。更换 IP、证书指纹或重启 APK 后需要重新配对。
- 原生请求只能访问 `/api/status`、`/api/pair`、`/api/sync`、`/api/dispatch`、`/api/monitor`、`/api/events`、`/api/events/read`、`/api/queue`，不允许 `/api/admin/*`、任意 URL、系统命令或网页随意执行的脚本。POST 必须用电脑端要求的 `X-Bridge-Request`；禁止 HTTP 和跨站跳转。
- 所有电脑请求在 Android 专用后台线程执行。系统文件导出继续使用 1.5 的 SAF 文件选择器；主控原始业务数据和 HUD 样式没有重写。
- 电脑同步端仍必须启用 1.6 的 **HTTPS + 加密保险库**；未启用其中一项时拒绝远程同步。

## 第一次配置（只有进入真机联调才需要）

1. 在可信电脑启动工程 `bridge/SETUP_AND_START_WINDOWS.bat` 或 Mac/Linux 对应的安全脚本。它会在本机建立 TLS 证书、加密保险库密码和桥接器。不要上传 `~/.personal-hub-bridge/security` 里的私钥、密码或任何业务备份。
2. 在同一台电脑上运行 `py -3 tools/show_bridge_fingerprint.py`（Windows）或 `python3 tools/show_bridge_fingerprint.py`（Mac/Linux）。显示：完整证书 SHA-256、证书覆盖的 IP SAN，以及到期时间。**电脑 IP 必须在证书 SAN 列表内**。如不在，停止测试，先安全更新电脑证书，且后续在 APK 重新核对新指纹。
3. 确认荣耀 V9 与电脑位于可信私有 Wi-Fi。进入 APK 的「多设备同步」，填电脑 IPv4、端口（默认 8765）、完整 SHA-256 指纹；直接从**电脑本机输出**复制或逐字核对，勾选确认后保存。
4. 在电脑终端读取 8 位临时码；手机上填写并配对。不要把临时 PIN、个人数据、私钥放到 GitHub Pages。
5. 初次同步前，**在来源设备先导出并核对一个可恢复的备份**。然后在 APK 同步页「预览差异」，逐项处理冲突；确认后才写入电脑及手机。更新只在主动点击时进行，不承诺后台实时自动同步。
6. 「电脑快捷指令」页可按「继续」「下一步」「修复并测试」等。手机请求到达已授权电脑桥时，电脑可能向前台允许的 AI 窗口实际输入文字并按回车。**发送前必须确认电脑焦点窗口**；接口返回 `sent_unconfirmed` 只表示尝试输入，不代表 AI 已收到或完成。

## 旧数据与升级原则

- **独立数据源**：GitHub Pages、浏览器端、电脑桥 `/hub/`、Android APK 各自有独立本地数据库。1.7 原生同步页读取的是 APK 同一源下的原始业务记录，不再需要先在电脑桥 `/hub/` 下重新录入。
- **不自动覆盖旧 APP**：不知道旧 APK 包名和签名之前，不能宣称这是无损升级；旧 APP 应保留，必要时使用旧 APP 自己的导出按钮导出 JSON，并在新 APK 中明确确认导入。不要卸载存有唯一记录的旧 APP。
- **局域网断连**：本机离线 CRUD 可继续；重新同步仍经过预览、版本 CAS、冲突选择及快照。若电脑成功写入而手机写入失败，页面会报告不确定状态，不应盲目重试同一操作。
- **电脑 TLS 证书过期或更新**：不能自动信任新证书，手机会提示检查；新证书应在电脑本机重新核对完整 SHA-256 后手工更新。
- **证书固定的代价**：更换电脑、网络地址、证书，往往需要重新配置；这是防止未知局域网设备伪装的安全权衡，不是公有 CA / 公网服务设计。

## 必须实测后才能称为“正式完成”

- 真实 Android SDK 构建 APK，检查 Manifest、版本码、内置资源和 V2 签名；CI 流水线运行通过。
- V9 上确认 WebView 支持 `WEB_MESSAGE_LISTENER`、SAF 保存/恢复、APP 重启持久化、设备后台/横屏行为、发热与续航。
- 在手机与电脑的实际局域网中，完整执行证书核对 → 配对 → 数据预览 → 冲突处理 → 同步 → 断网重连、电脑指令白名单与电脑本机授权。
- 用真正已装旧 APK 的 `applicationId` 和证书指纹证明升级路径；否则仅做独立安装或明确备份迁移。
- 华为运动健康自动读取及跨应用检测所有 ChatGPT 网页任务完成状态仍未实现，不应作完成承诺。
