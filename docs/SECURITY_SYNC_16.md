# 电脑桥 v1.6：安全边界和使用限制

## 威胁模型

1. 局域网其他设备能看到未加密的 HTTP 请求：1.6 默认拒绝手机端 HTTP 页面和配对；只有 HTTPS 才允许移动设备访问。`--allow-insecure-lan` 是明确的危险调试开关，不适合私人数据。
2. 电脑同步仓库明文被复制：启用 `--vault-passphrase-file` 后，主仓库与历史副本按 AES-256-GCM 加密，scrypt (N=16384,r=8,p=1) 从本机密码文件派生密钥，认证标签失败即拒绝继续。
3. 两个电脑桥进程同时写：版本号 CAS + 操作系统独占文件锁保护读改写序列，拒绝超时锁争用。
4. 流量从互联网被转发或代理：**不支持公网端口映射、反向代理或云发布**。127.0.0.1 的放宽只用于本机调试，不代表在反向代理后安全。
5. 本机账户已遭入侵：攻击者能读取用户目录内密码文件时仍可解密，需依赖设备系统磁盘加密、登录安全和单独离线备份。不能把本轮保护描述为零知识云端加密。

## 配置与证书信任

推荐使用独立虚拟环境脚本在电脑生成证书与密码。生成文件路径：

- `~/.personal-hub-bridge/security/server.crt`：自签名服务端证书，可向外展示其指纹但不代表自动可信。
- `~/.personal-hub-bridge/security/server.key`：TLS 私钥，**不得提交仓库**。
- `~/.personal-hub-bridge/security/vault-passphrase.txt`：随机保险库密钥，**不得提交仓库**。

配置会打印证书 SHA256 指纹，可与独立渠道核对。证书包含生成时所检测到的电脑 IP 的 SAN；若路由器更换后 IP 改变、证书过期，客户端需重新信任新证书。脚本**不会自动覆盖证书或密码**，以免旧数据失去解密能力。

**重点限制**：自签名服务端证书并不会被 HarmonyOS 浏览器自然信任。本轮没有提供浏览器内安全导入/绑指纹机制；不建议把自签名证书当作全局 CA 安装到手机，也不要点击「继续访问不安全站点」传输真实健康/求职记录。真正的原生 HTTPS 证书固定和无感配对需要在 Android 工程中单独完成并真机验证。

## 旧明文保险库

如果早期电脑桥已创建 `~/.personal-hub-bridge/sync-main.json`，1.6 启用保险库密码后将拒绝静默打开早期 `format:1` 明文文件。这是故意的数据保护措施：

1. 请先将旧电脑同步文件及 `sync-history` 目录做**离线加密备份**，不要通过公开 GitHub 仓库、聊天或网盘明文分享。
2. 在独立目录做迁移测试，验证旧记录和修订号完整，确认有实际恢复路径。
3. 只有确认记录成功迁移后，才允许将新加密文件作为活动仓库；不得为了让服务启动而直接删除唯一旧数据。

本轮未提供自动就地迁移，因为在缺少老数据实际结构和实机恢复测试时，自动覆盖比拒绝更危险。

## 接口要求与实际已测试范围

- 手机访问地址：`https://电脑局域网IP:8765/`，配对的 PIN 属于本次电脑桥进程，不持久化。
- `GET/POST /api/sync` 远程调用必须 `TLS == true` 且 `vault_encrypted == true`；不通过返回 HTTP 426。
- POST 使用 `Origin` 精确匹配、同源自定义请求头和 cookie；TLS cookie 带 `Secure; HttpOnly; SameSite=Strict`。
- 写盘加密使用随机盐与 nonce，写入过程为临时文件 + fsync + 原子替换，保留最近八份加密历史。
- 已在当前环境用 Python TLS 信任根测试完成真实 HTTPS loopback 握手、PIN 配对、Cookie 和保存；**没有验证荣耀 V9 浏览器证书信任，也未验证 2 台物理设备**。
